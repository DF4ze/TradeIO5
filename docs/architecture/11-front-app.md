# Application utilisateur `/app` (front)

Vérifié le : 2026-11-07. Charte : [`../graphique/charte-graphique.md`](../graphique/charte-graphique.md) ; données affichées : [`../graphique/inventaire-options-affichage.md`](../graphique/inventaire-options-affichage.md) ; endpoints : [`../api/rest-endpoints.md`](../api/rest-endpoints.md).

## Pages

`AppPageController` (`@PreAuthorize("isAuthenticated()")`) sert une coquille Thymeleaf par page ; **aucune donnée de trading dans le rendu serveur** : tout vient des `/api/**` chargés par le navigateur. Le serveur pose seulement `data-theme` (préférence), `data-mode` (Simple / Avancé / Expert), `data-user`, `data-page`, `data-symbol`.

Avancé : part vendable de la position (`bagPercent`, 100 % par défaut, plafonne les ventes) et achat minimum (`minBuyUsd` : en dessous, l'achat est reporté en carry) |

| `/app/journal` | Une carte repliable par jour (le plus récent déployé ; résumé : achats, ventes, bloqués, en attente, rien à faire, alertes ; statut du plan, coût, expiration). ## Pages publiques (visiteur)

`MainController` sert, hors `AppPageController`, trois pages sans donnée serveur : `/` (présentation : accroche, couverture multi-actifs / multi-plateformes, fonctionnement, aperçus statiques des widgets en SVG/CSS à données fictives, transparence, avertissement de risque, pied de page à liens vides), `/login` et `/register` (cartes de la charte, lien retour à l'accueil, pas de choix de rôle). Un utilisateur connecté est redirigé vers `/app`. Gabarits : `templates/home.html`, `login.html`, `register.html` et `fragments/public.html` (`head`, `topbar`, `footer`). Le logo et les icônes viennent de `fragments/brand.html` (`logo`, `icons`), inclus par `fragments/public.html` et `app/fragments.html` (cf. [charte, section Logo](../graphique/charte-graphique.md)). Styles : `css/public.css` en plus de `tradeio.css` ; `js/public.js` applique le thème (sombre par défaut, bascule clair mémorisée dans `localStorage` du navigateur, jamais côté serveur car le visiteur n'a pas de préférences). Le thème de l'application est **sombre uniquement** (`AppShell` force `dark`, plus de bascule). `/admin` (6 onglets : Console, Credentials, Bindings, Testeur d'ordre, Journal, Modulation) utilise la même coquille et les mêmes tokens (classe `tio tio-admin`, thème sombre) ; `css/admin-compat.css` rend les anciennes classes de mise en page (grille, boutons, alertes, tableaux, onglets) sur les tokens de la charte, sans Bootstrap ; `js/admin-tabs.js` gère les onglets. Habillage Admin : bandeau d'état en tuiles, onglets en pilule défilante, chaque onglet actif est une carte de la charte (filet spectre, titre à point violet), blocs secondaires en sous-tuiles, tableaux arrondis, étapes de la Console numérotées en pastilles dégradées. Leurs scripts restent sous `/assets/js/admin/`.

### Console admin (onglet Console)

Filtres jour UTC (◀ ▶, « Tous les jours »), utilisateur, statut ; actions du jour (`Lancer la passe`, `Resynchroniser`, `Planifier tous`, kill switch `Lever`/`Réengager`) ; chips de statut (comptes avant filtre statut, clic = filtre) ; tableau de tous les plans (case, jour, user, révision, statut, actifs/étapes, armé, confirmé via `GET /api/admin/bindings`, blocage, ▸) ; barre d'actions groupées (Réinitialiser / Armer / Exécuter / Réconcilier) qui appelle d'abord `dryRun` (éligibles X / N, inéligibles expliqués par la table unique `BULK_REASONS` de `admin-core.js`) puis l'appel réel ; **Exécuter** passe par une modale native `<dialog>` (`AdminCore.askConfirm` : récap plans / ordres / total USDC / users, saisie de `EXECUTER`) ; résultat par plan avec « Relancer les erreurs ». Le détail (▸, un seul plan ouvert) affiche le résumé et la procédure individuelle en 7 étapes. L'éligibilité d'un lot n'est jamais recalculée en JS. Endpoints : cf. [plan d'ordres, actions groupées](10-execution-plan.md). Toute action de la Console est **exclusive** : les contrôles sont verrouillés tant qu'elle dure (un lot peut prendre 30 s et plus) et le tableau est rechargé après une erreur ; après un reset unitaire, le détail suit la nouvelle révision (un reset crée un nouveau plan d'id différent, l'ancienne révision passe `SUPERSEDED` et disparaît de la liste).

## Modes d'affichage

Préférence serveur `displayMode` (`PUT /api/user/preferences`). Simple : décisions, PnL, montant de base, mode d'exécution, prix moyen. Avancé : + bande, puissance, biais, plafonds, part de la position offerte, achat minimum, reporté. Expert : + journal brut de modulation et lien vers l'Espace Expert (`/app/expert`).

## Mode démo

`?demo=1` : jeu de données fictif côté navigateur (`demo.js`), mêmes formes que l'API, aucun appel réseau. Réglages (préférences, modulation) gardés en mémoire de la page ; mode d'exécution, confirmation du 1ᵉʳ ordre, clés et création de lien sont refusés. Ne touche jamais au kill switch ni à l'exécution.

## Organisation du code statique (`static/assets/app/`)

- `css/tradeio.css` : tokens (sombre par défaut, clair via `data-theme="light"`, mêmes noms) et composants ; polices Manrope locales (`fonts/`), Lightweight Charts v4 locale (`vendor/`).
- `js/core.js` (DOM sans HTML injecté, `TIO.api` : 401/403 → `/login`, formats « — »), `ui.js` (carte, pastille de statut, puces, segmenté, interrupteur, barre, curseur, jauge en arc, états chargement / vide / erreur, libellés), `charts.js` (courbes SVG), `asset-chart.js` (fiche), `explain.js` (frise et « Pourquoi ce montant ? »), `demo.js`, `app.js` (démarrage), `page-*.js` (une par page).
- **Espace Expert** : `js/expert-common.js` (`TIO.expert` : requêtes avec `code`/`details`, modales maison, garde « modifications non enregistrées », formulaire généré depuis `TREND_FIELDS` / `RAINBOW_GROUPS`, sélecteurs, plage, mémoire locale, simulation + polling, fenêtre de résultats, panneau de simulation), `js/expert-preset-screen.js` (écran preset commun Trend / Rainbow), `js/expert-chart.js` (`TIO.expertChart(conteneur, {kind})` : 4 graphiques Lightweight Charts empilés et synchronisés — prix + bandes + marqueurs + phases / zones inactives grisées, poche, PnL, exposition ; zones inactives grisées aussi sur poche / PnL / exposition ; curseur vertical synchronisé sur tous les graphiques ; PnL et exposition : $ à gauche, % du capital à droite (séries jumelles invisibles) ; poignée de redimensionnement sous chaque graphique (hauteur mémorisée) ; interrupteurs d’affichage dans l’en-tête de chaque graphique (un graphique désactivé garde son en-tête seul), dont la courbe DCA fixe du PnL ; outils de lecture sur le graphique de prix (`MeasurePrimitive`, canvas) : Shift+clic = mesure (2 clics : % , barres, durée), Ctrl+glisser = totaux achats / ventes de la zone, clic ou Échap = effacer ; zones inactives toujours grisées ; options mémorisées par type, `localStorage` `tio.expert.chart.v2.<kind>` (hauteurs : `tio.expert.chart.v2.h.<kind>.<panneau>`) ; détail du jour au survol / clic), `js/page-expert-{trend,rainbow,affectation}.js`. Chargés par le fragment `scripts` quand `page` commence par `expert`. Aucun appel en `?demo=1` (message « Pas de démo »).
- Icônes crypto : `img/crypto/<symbole en minuscules>.svg` (483 SVG couleur du jeu spothq/cryptocurrency-icons, licence CC0, `LICENSE-CC0.md` joint) + `crypto-icons.json` (liste des symboles disponibles, chargée une fois). `ui.coin(symbole)` est le point d'appel unique des pastilles d'actif : glyphe/dégradé par défaut, remplacé par l'icône si le symbole est dans la liste, retour au glyphe si le chargement échoue. Symbole sans icône (ex. XAU) ⇒ glyphe. Ajouter un actif = déposer `<symbole>.svg` et l'ajouter à `crypto-icons.json`.
- Règles : `textContent` / création de nœuds uniquement (test `AppPageControllerTest` interdit `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval(`) ; couleurs lues dans les variables CSS ; un widget en échec n'empêche pas les autres (`ui.widget`) ; donnée absente ⇒ « — ».

## Infobulles (`ui.js`)
Un seul style (`.tip`, celui du camembert) et un seul point de création : `ui.tipEl()` (élément), `ui.tooltip(wrap)` (survol : graphiques, camembert), `ui.bubble(opener, contenu, titre)` / `ui.closeBubble()` (clic : détail du Journal ; fermeture ×, Échap, clic extérieur ; feuille en bas d'écran en mobile). Ne jamais créer d'infobulle ad hoc.
Tout attribut `title` passé à `h()` devient `data-tip` (jamais d'infobulle native du navigateur) ; `ui.js` affiche `[data-tip]` au survol/focus avec ce même style.
