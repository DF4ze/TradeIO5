# Optimiseur — évaluateur + moteur de recherche (`service/optimizer/`)

Vérifié le : 2026-11-16 (`service/optimizer/**`, `controller/AdminOptimizerController`, tests `service/optimizer/*`). Rejeu évalué : [`13-espace-expert.md`](13-espace-expert.md) et [`13a-rejeu-politique-ath-couts.md`](13a-rejeu-politique-ath-couts.md). Cadre, méthode et mesures : [`../etudes/etude-optimisation-mode-autonome.md`](../etudes/etude-optimisation-mode-autonome.md) §11.

Hors ligne : ne touche ni le live, ni la base (aucune migration), n'appelle aucun exchange (hors chargement habituel des bougies). Tout en USDC. Une politique L2 = bande par régime (`RegimeBandPolicy`) + plafond de mise ATH (`AthCap`) + multiple du montant de base de référence (`baseMultiplier`).

## Évaluateur : `ReplayScorer`
`ReplayScorer.score(ScorerInputs, ResolvedCandidate, CostMode, shortWindowOnly) → ScoreReport` : fonction pure, thread-safe, **aucune valeur par défaut dépendant de l'horloge, du wallet réel ou des réglages utilisateur**.
- **`ScorerInputs`** (tout explicite) : liens (`LiveSlot` + `LinkSignalReplay.Config` portant les bougies + étiquette de source), capital de départ, **date de fin commune**, réglages de modulation de base (neutres par défaut), bornes admin (`RainbowModulationControl`), profil, fenêtres, pénalité de dispersion, mise finale max, coûts du mode complet. Les bornes de plage des `Config` sont ignorées : les fenêtres sont recalculées depuis la date de fin.
- **Fenêtres** ancrées sur la même date de fin : `12m` (poids 3), `24m` (2), `full` (1, depuis le premier jour rejouable de tous les liens). Une fenêtre peut avoir une date de début explicite (`WindowSpec.from`, utilisée par les fenêtres de test). Une fenêtre non éligible (historique insuffisant, aucun jour rejouable) est **exclue et listée** dans `excluded` avec son motif, jamais remplacée. **Seules les fenêtres bornées** (`months` non nul : 12 m / 24 m / test) sont *notées* (`WindowReport.scored()`) : l'historique complet est rapporté (gain, drawdown) mais n'entre ni dans le score, ni dans la dispersion, ni dans le timing pur, ni dans le veto de drawdown. Aucune fenêtre notée éligible ⇒ veto `NO_ELIGIBLE_WINDOW`.
- **Référence commune, même budget** : le DCA fixe partage le cash commun de la stratégie (tout-ou-rien, jamais au-delà du cash, aucune recharge ; `WindowReport.fixedMinCash` ≥ 0). Il est **toujours** calculé à la base de référence du lien (`ReferenceBase` : logique de proposition d'onboarding `RainbowLiveOnboardingService.referenceBaseAmount` = cash alloué / (`autonomyDays` × multiplicateur moyen), cash réparti à parts égales entre liens), identique pour tous les candidats ; la base de la stratégie = `baseMultiplier` × cette base (`LinkSignalReplay.Config.fixedBaseAmount`). Gain = (valeur finale − valeur finale du DCA fixe de référence) / **capital**, en %. La référence dépense tout le capital en quelques mois (base × jours actifs) : sur une fenêtre haussière elle peut finir > 2× le capital, d'où des gains très négatifs hors fenêtre de test (c'est un effet de timing du marché, pas une dépense hors budget).
- **Par fenêtre** : valeur finale, DCA fixe de référence, gain (USDC, % du capital), drawdown max (`DrawdownMeter`), exposition moyenne, répartition exposition / timing / frais (`EpisodeTimeline`), jours bloqués, achats / ventes, mise finale, cash minimal.
- **Score** = médiane pondérée du gain % des fenêtres notées − `λ` × écart absolu moyen pondéré autour de la médiane (`λ` = `OptimizerDefaults.DISPERSION_PENALTY`, paramétrable). Jeu vetoé ⇒ `VETO_SCORE` (−1000) ; `rawScore` garde le score sans veto.
- **Vetos** (`Vetoes`, fonction pure) : drawdown d'une fenêtre *notée* (pas l'historique complet) sous le plafond du profil (`RainbowModulationControl.drawdownCaps`, absent pour `CUSTOM`) ; dégénéré (ne vend jamais **ou** ne rachète jamais sur la plus longue fenêtre éligible) ; capital dépassé (cash < 0, invariant du wallet fermé) ; mise finale > `maxFinalStakeMultiple` (25 × la base par défaut).
- **Timing pur** (rapporté à part, **jamais dans le score**) : terme « timing » de `EpisodeTimeline` (gain à exposition égale), en % du capital, médiane pondérée des fenêtres ; définition dans `ScoreReport.PureTiming`.
- **Empreinte des bougies** par actif (`CandleFingerprint` : premier / dernier jour, nombre, somme de contrôle SHA-256 tronquée des bougies ≤ date de fin) dans chaque rapport.
- **Deux modes de coûts** (`CostMode`) : `SIMPLIFIED` (taux constant par ordre, sans spread ni minimum) ; `COMPLETE` (`OrderReplay` sur barème **statique** `OptimizerCosts` : frais, demi-spread, slippage, minimum d'achat, lot ; aucun appel exchange).
- **`Candidate`** (nom → valeur) est traduit par un `CandidateAdapter` en `ResolvedCandidate(policy, athCap, baseMultiplier)` ; le scorer ignore les noms. Espace L2 : `L2Params` (`bullMin`, `bullMax`, `bearMin`, `bearMax`, `buyCap`, `baseMultiplier` 0,5–2 par cran de 0,25) ; départ = bandes 20–90 / 0–30, plafond d'achat du profil (aussi sa borne haute), multiple 1 ; vente ATH = celle du profil. `L2Params.validator` : `min < max` et largeur ≥ largeur minimale admin par bande ; un candidat invalide est rejeté **sans rejeu** (veto `INVALID_CANDIDATE`) et compté dans les essais.

## Moteur de recherche : `SearchEngine`
Ne connaît ni les noms de paramètres ni le simulateur (`SearchObjective` : `evaluate(Candidate, Fidelity, Scenario)`).
- **`ParamSpace`** : paramètres typés (continu, entier, catégoriel), bornes, pas (« cran »), état gelé ; sérialisable.
- **Étapes** : (1) sensibilité un paramètre à la fois autour du point de départ, effet mesuré entre jeux **non vetoés** (`vetoedPoints` rapporté à part ; un paramètre qui déclenche des vetos n'est jamais gelé), classement décroissant, gel sous `FREEZE_THRESHOLD` ; (2) Sobol déterministe (graine fixe, décalage Cranley-Patterson) sur les paramètres libres ; (3) successive halving : fenêtre 12 m simplifiée → toutes fenêtres simplifiées → coûts complets pour les finalistes ; (4) plateau : score d'un candidat = médiane de ses voisins à ±1 cran, le centre du plus grand plateau est retenu ; (5) raffinement local autour du meilleur plateau. Pas de montée par coordonnée.
- **Bousculades** du candidat retenu : date de fin décalée de 1 / 7 / 15 / 30 jours, voisins ±1 cran, mondes alternatifs si fournis (source de bougies ; le chargeur d'entrées n'en charge pas : aucune bougie d'une autre source n'est lue) ; **verdict de robustesse** explicite (écart relatif toléré `ROBUSTNESS_TOLERANCE`, plancher du dénominateur `ROBUSTNESS_FLOOR`).
- **Exécution** : pool dédié (taille configurable, jamais celui des simulations utilisateur), annulable (`SearchControl`), progression (fraction + étape), compteur d'essais exact (mémoïsation exclue). Constantes (fenêtres, poids, seuils, graine, tailles) : `OptimizerDefaults`.

## Rapport : `OptimizationReport` (JSON)
Entrées (espace demandé et gelé, graine, réglages de recherche, fenêtres, capital, date de fin, profil, sources, empreintes), sensibilités ordonnées, candidat retenu + plateau + finalistes, scores par fenêtre, timing pur, bousculades, vetos rencontrés, nombre d'essais + rappel que la barre de significativité monte avec lui, durées dans un bloc **`timings` séparé**. Mêmes entrées et même graine ⇒ JSON identique à l'octet près hors `timings` (`toJsonWithoutTimings()`).

## Lancement
- **Runner manuel** : `OptimizerManualRunnerTest` (`-Doptimizer.manual=repro|l2|policy|preset|preset-cadences`, base locale copie de prod, jamais dans la suite normale ; `-Doptimizer.freeze=<paramètres>` gèle des paramètres). Sorties `target/optimizer-*.md|json`.
- **Endpoint admin** (`ROLE_ADMIN`, **désactivé par défaut** : `tradeio.optimizer.enabled=false` ⇒ beans absents, 404) : `POST /api/admin/optimizer/runs` (202 ; corps `OptimizerRunRequest` : `asset`, `walletId`, `cash0`, `endDate`, `profile`, facultatifs `baseAmount` = surcharge de la base de référence, `seed`, `sobolSamples`, `mode` = `ASSET_L2` (défaut), `POLICY_L2` ou `PRESET_L1`, `profiles`, `links`, `foldEnds`), `GET /api/admin/optimizer/runs/{id}` (état, progression, rapport JSON une fois `DONE`), `DELETE` (annule). Un seul run à la fois (409), résultats en mémoire avec durée de vie (`tradeio.optimizer.result-ttl-minutes`, 30), pool d'évaluation `tradeio.optimizer.pool-size` (2) ; lancement tracé au journal admin (`AdminAction.RUN`, cible `optimizer:<actif>`) ; aucune persistance.
- **Entrées chargées** par `ReplayInputsLoader` : un seul actif, lien actif du wallet demandé, bougies de la source du lien sans fallback (cache DB habituel), sans coûts réseau ; `endDate` ≤ dernier jour clos.

## Calibrage de la politique : mode `POLICY_L2`
`PolicyCalibrator` (pool dédié) calibre chaque profil (Prudent, Équilibré, Dynamique, Full) sur un **wallet de référence** (`ReferenceWallet`, chargé par `ReplayInputsLoader.loadReferenceWallet` : BTC + ETH + PAXG, cash commun, 10 000 USDC, sources = bougies par défaut du lien, empreintes dans le rapport). Même garde-fous que `ASSET_L2` (admin, désactivé par défaut, un run à la fois, mémoire + TTL ; cible tracée `optimizer:policy-l2`). Rien n'est appliqué aux réglages ni aux presets, rien n'est persisté (pas de migration).
- **Plis annuels** (`CalibrationConfig`, défauts dans `OptimizerDefaults.FOLD_ENDS`) : entraînement 12 m ×3 / 24 m ×2 / complet ×1 finissant en T ∈ {2023-11-15, 2024-11-15, 2025-11-15}, test = 12 mois suivants (T+1 → T+12 mois, `WindowSpec.from`). Aucun recouvrement ; les bougies sont **coupées** à T (entraînement) et à la fin du test : aucun indicateur ne voit le futur.
- **Lien inéligible** sur une fenêtre d'entraînement ou de test d'un pli (`ReplayScorer.ineligibleLinks`) ⇒ exclu de ce pli, signalé dans `FoldInfo.excluded` (PAXG : Kraken D1 depuis 2025-04) et, quand c'est un manque de bougies, par un statut explicite `HISTORIQUE_INSUFFISANT` (`FoldInfo.history` : actif, fenêtre, bougies disponibles / requises ; `ReplayScorer.historyStatuses`). L'optimisation par actif (étape 5) s'appuie sur ce statut.
- **Par pli** : recherche `SearchEngine` depuis le point de départ du profil (veto drawdown = plafond du profil, `buyCap` borné par le défaut du profil), puis évaluation hors échantillon du candidat retenu **et** du point de départ.
- **Pli à entraînement vetoé** (`PolicyCalibrator.trainBlocked`) : si le candidat retenu est vetoé (donc tous les candidats, y compris un `INVALID_CANDIDATE`) **ou** si le point de départ est vetoé à l'entraînement, le pli donne `foldDecision = GARDER_DEPART`, `foldReason = ENTRAINEMENT_VETOE` : aucun candidat retenu (`chosen` nul), jamais un candidat invalide ; le départ reste rapporté en test, le motif du veto du départ dans `trainVetoesStart`. Le pli n'est pas gagné.
- **Règle** (`PolicyVerdict`, pure) : `ADOPTER` si la politique bat le départ sur la majorité des plis (plis/2 + 1), sans veto bloquant en test (drawdown, capital, mise finale ; « dégénéré » seulement rapporté) et médiane hors échantillon ≥ 0 % du capital ; sinon `GARDER_DEPART` (résultat nul valide).
- **Rapport** `PolicyCalibrationReport` : entrées (wallet, plis, empreintes, graine), par profil et par pli (candidat retenu, score d'entraînement, gain hors échantillon retenu vs départ, vetos, timing pur, sensibilités), stabilité des paramètres, verdict + motif, nombre d'essais (tous plis), mesure de la pénalité de dispersion (`PenaltyMeasure` : part de la pénalité dans le score ; calculée sur les seules fenêtres 12 m / 24 m ; alerte si la médiane dépasse `PENALTY_SHARE_ALERT` = 50 %). Octets identiques à entrées égales hors `timings` (`toJsonWithoutTimings`).
- Protocole alternatif **opt-in** `CalibrationConfig.protocolV6()` + `V6_REFERENCE_AUTONOMY_DAYS` (360 j) : défauts, endpoint et live inchangés ; bascule = un appel, retour = ne pas l'appeler. Mesures : [étude](../etudes/etude-calibrage-politique-l2.md).
- Variantes expérimentales (runner `-Doptimizer.manual=policy-variants`, jamais par défaut) : `CalibrationConfig.withVariant(trainDrawdownVeto, dropFoldOnStartVeto)` (veto de drawdown à l'entraînement ; pli écarté si le départ est vetoé), `withStart` (valeurs de départ), `withFolds` (plis et durée de test) et `ReferenceWallet.autonomyDays` (étalement de la référence).
- Mesures et verdicts : [`../etudes/etude-calibrage-politique-l2.md`](../etudes/etude-calibrage-politique-l2.md).
