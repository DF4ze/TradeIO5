Info — test d'un achat BTC sur Kraken depuis l'interface

Le client Kraken n'a jamais passé d'ordre réel. Commence par le « Valider » du testeur d'ordre (aucun ordre créé). Toutes les actions se font dans la page page Administration.
0. Prérequis (hors interface)
  • application-dev.properties : tradeio.execution.mode=LIVE et tradeio.execution.live-unlocked=true ; variable d'environnement TRADEIO_MASTER_KEY définie ; redémarrer l'application.
  • Bandeau Admin : mode LIVE, déverrouillé, clé maître OK, kill switch engagé, port Kraken présent.
1. Credentials (Admin → Credentials)
  • Clé TRADE Kraken présente et activée (droits « créer/annuler des ordres » uniquement, jamais de retrait).
  • Le catalogue Kraken doit avoir native_pair renseigné, sinon PAIR_UNKNOWN (il se remplit au prochain rafraîchissement).
2. Testeur d'ordre (Admin → Testeur d'ordre) — aucun ordre créé
  • User, exchange Kraken, paire BTC (BTC-USDC), BUY, taille minimale (≈ 0,0001 BTC), plafond de prix au-dessus du marché, puis « Valider ».
  • Le testeur est soumis au kill switch : « Lever » dans le bandeau du haut avant « Valider », puis « Engager » après le test.
  • Attendu : contrôles locaux tous OK et accepted. Un blockedBy indique le verrou manquant.
2 bis. Ordre réel direct depuis le testeur (optionnel)
  • Même saisie qu'au point 2, kill switch levé (bandeau), puis switch rouge « Ordre RÉEL », saisie de ENVOYER et « Envoyer l'ordre RÉEL ». Le plafond absolu par ordre s'applique ; le kill switch est rengagé automatiquement.
  • Un vrai ordre limit IOC part et l'état, le prix moyen et les remplissages s'affichent. Si l'issue est inconnue (UNKNOWN) ou non terminée : « Réconcilier » relit l'ordre par clOrdId, sans jamais le renvoyer.
  • Cet ordre n'est pas enregistré dans la table transaction : contrôle côté Kraken.
3. Binding (Admin → Bindings)
  • Binding BTC sur le wallet Kraken, preset au choix, bagPercent faible.
  • Activer les presets liés dans la page Rainbow live (un preset inactif ne produit aucun snapshot), activer « Exécution » du binding, puis « Vérifier » (OK ou via intermédiaire).
4. Passe puis plan (Admin → Console, étape 1)
  • « Lancer la passe » (jour = hier, bougie D1 complète) puis « Planifier » (même jour).
  • L'action live BTC doit être BUY, sinon il n'y a aucun ordre à envoyer ce jour-là.
  • Contrôler dans le plan : paire, taille, plafond de prix, coût.
5. Armement et exécution (Admin → Console)
  1. « Armer » (admin).
  2. Confirmation du 1ᵉʳ ordre par le propriétaire (page Rainbow live).
  3. « Lever » le kill switch, puis « Exécuter » : il se réengage automatiquement en sortie.
  4. Étape UNKNOWN ou EXECUTING : « Lever » puis « Réconcilier » (relecture par clOrdId, aucun renvoi).
6. Contrôle
  • Console : statut FILLED/PARTIAL et audit des événements ; Journal : ARM_BINDING, RUN, AUTO_REENGAGE.
  • Côté Kraken : ordre dans l'historique, frais en cotation.
  • En cas de doute : mode=DRY_RUN, l'exécuteur n'appelle plus jamais le port. Plafond absolu par ordre toujours appliqué.
